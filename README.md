# Translate to Code

一个面向 Python 开发的 Codex 技能：先用自然语言描述设计，得到用户批准后，由子 agent 按模块实现和测试，再交给用户验收。适合希望逐步审阅设计、控制改动范围的开发任务。

## 使用条件

- 使用支持本地技能及子 agent 委派的 Codex 环境。
- 运行代码或测试时，需要目标项目相应的开发环境。
- 技能使用中文描述；实际工作使用用户所使用的语言。

仅解释代码、审查代码或修改文档时，不自动使用此技能。如果子 agent 不可用，技能会暂停实现，等待用户明确允许由主 agent 代为实现。

## 安装

将本仓库克隆到个人技能目录：

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/LovelyBear2004/skill.git ~/.agents/skills/translate-to-code
```

如果目标目录已经存在，先确认其中内容，避免覆盖已有技能。安装后在下一轮对话中使用；若技能未出现，重启 Codex。

也可以使用 Codex 的技能安装器，并明确仓库根目录是技能目录：

```text
$skill-installer 从 https://github.com/LovelyBear2004/skill 安装仓库根目录的技能，命名为 translate-to-code。
```

## 使用示例

在 Codex 中输入：

```text
$translate-to-code 写一个计算斐波那契兔子序列的 Python 程序。
```

1. 主 agent 阅读项目，写出模块设计，说明目标位置、输入输出、数据格式、修改范围及验收方式。
2. 用户审阅设计后回复“允许进行”，批准当前模块的实现；也可以明确批准多个模块。
3. 主 agent 委派子 agent 实现当前模块并运行相关测试。
4. 主 agent 审查修改和测试结果，提交用户检查。用户回复“OK”后，该模块归档为已验收。
5. 按依赖顺序处理后续模块；已有的明确批准继续有效。

“OK”默认只验收当前模块，不自动批准下一模块。用户可以明确调整流程或批准范围。

## 模块状态

模块使用唯一编号，例如 M-001，并在 Python 独立注释行或设计文档中记录状态：

| 标记 | 含义 |
| --- | --- |
| `## [M-001] 待批准` | 设计完成，等待实现许可 |
| `##** [M-001] 已批准` | 当前允许实现 |
| `###*** [M-001] 待验收` | 实现和相关检查通过，等待用户检查 |
| `# [M-001] 已验收` | 用户验收通过 |

设计阶段不修改可执行代码。新文件还不存在时，先在设计文档中说明实现位置，批准后再创建文件。
